# Architecture and invariants

The browser talks exclusively to Rails through a same-origin `/api/v1` proxy. React Router handles public/admin/student navigation; TanStack Query holds transient server state; React Hook Form + Zod validates registration/program forms. Reusable button/dialog primitives follow shadcn conventions; Radix supplies dialog focus management. Tailwind is integrated alongside a purpose-built responsive visual system.

Rails retains ActionController’s cookie/session/CSRF middleware and exposes JSON controllers. Devise hashes passwords, creates recovery tokens and authenticates sessions. A database-backed session version invalidates prior cookies at logout (signing the user out on every device). Password setup tokens expire in six hours. A separate invitation_pending flag distinguishes pending students from disabled accounts. Disabled users are denied even if they already have a session. Pundit policies authorize every private controller action and scope queried records to the current user. Student endpoints never accept identity from the browser. Raw Active Storage routes are disabled; PDFs are delivered only by an authenticated, scoped controller.

Enrollment holds a PostgreSQL row lock on its program while checking capacity and creating the record. A unique index prevents duplicate enrollment, including re-enrollment after withdrawal. Eligibility is explicitly confirmed by an admin. Program state transitions are explicit. Once enrollment exists, program dates cannot be edited. End states for enrollments are terminal; progress alone cannot indicate success. Completed enrollment requires 100 percent progress and a completion timestamp. Students cannot mutate progress.

Certificate issuance locks an enrollment, checks both successful student completion and program completion, snapshots original details, and attaches a Prawn PDF. Unique enrollment and certificate-number indexes make retries idempotent. A revoked certificate remains revoked during ordinary retry. Reissuance is an explicit admin action with a new number and audit record of the previous number. Downloads deny revoked records. A worker retry handles temporary failures; generation status is exposed to administrators. The issuance transaction can roll back a first-time failure before a certificate exists; monitor Sidekiq dead jobs as well as report counts. Storage and database backups must be coordinated.

No Aadhaar is collected or stored. Profile photo attachment validates size and MIME type in Rails; a photo upload/display interface is not yet included. Audit metadata is allowlisted and excludes secrets. Foreign keys and restrictive associations preserve history; deactivate accounts instead of deleting them. Dashboard reports are aggregates; collection endpoints paginate up to 100 records. The first version is single-organization with only admin/student roles.

Deployment diagram: Browser → HTTPS proxy → static React assets / Rails API → PostgreSQL + private storage. Rails → Sidekiq/Redis → PDF generation and attachment. SMTP delivers invitations; local Mailpit captures them.
